# DayLens Stage D Reliability and Performance Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Measure and improve DayLens sampling, playback evidence, dashboard query cost, report traceability, and module boundaries without changing trusted time totals before replay evidence exists.

**Architecture:** Introduce pure measurement evidence models and an aggregate-only shadow recorder beside the current tracker. Keep the existing boolean playback and fixed-duration accounting as compatibility adapters for this release. Cache only completed historical dashboard data, move heavy statistics loads off the GUI thread, and add deterministic report timestamps/ranges without adding a database or paid AI request.

**Tech Stack:** Python 3.12, PySide6, SQLite, pytest, PyInstaller, Windows Core Audio.

---

- [x] Add failing tests for monotonic sample observations, clock rollback, bounded aggregate shadow state, and privacy-safe persistence.
- [x] Add `src/daylens/measurement.py` with immutable sample/playback evidence models and pure observation helpers.

- [x] Add a read-only benchmark command under `tools/` that reports p50/p95 latency, SQL count, peak memory, and database size for the dashboard snapshot.
- [x] Run the focused tests and capture the real-database baseline in the Stage D result document.

### Task 2: Add playback evidence without changing accounting
