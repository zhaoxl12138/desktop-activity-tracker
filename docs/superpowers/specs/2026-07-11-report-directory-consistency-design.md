# DayLens 报告目录一致性修复设计

## 目标

确保主窗口、报告中心、软件统计页和托盘始终使用同一个报告根目录，尤其是在用户切换数据库路径并重启后；移除设置页中实际不可配置的伪入口。

## 统一目录来源

GUI 启动时继续以当前数据库所在目录为基础生成 `<数据库目录>/reports`。`gui_bootstrap` 将该路径同时传给 `MainWindow` 和 `TrayManager`。托盘生成日报、手动生成日报和打开报告目录都使用构造时收到的路径，不再自行调用 `get_data_dir()` 推导另一个位置。

数据库路径变化会触发既有自动重启。新进程启动后重新解析报告目录，因此数据库和报告目录保持绑定，不做运行时动态迁移。

## 设置页呈现

“报告输出路径”仍显示供用户确认，但设为只读并移除浏览按钮。提示文字明确说明该目录随数据库位置自动确定。数据库文件和 Obsidian 输出路径继续可配置。

## 测试

1. `TrayManager` 接收并保存统一的 `reports_dir`。
2. 托盘自动生成、手动生成和打开目录都使用该路径。
3. GUI bootstrap 用同一参数构造主窗口和托盘。
4. 设置页报告目录输入框只读且不存在可触发的浏览按钮。
5. 完整测试、编译、发布构建、快捷方式与进程路径验证通过。

## 范围外事项

本批不允许独立配置报告目录、不迁移历史报告、不改变报告的 daily/weekly/monthly 子目录结构。
