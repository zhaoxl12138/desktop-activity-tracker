# DayLens V1.7 每日目标与执行偏差设计

## 范围与原则

V1.7 实现用户主动设置的每日 1～3 项目标、可信投入与目标差值、用户手动确认的成果，以及现有周报中的分层回顾。不改写 V1.6 任务归属、原始会话、分类、时间统计或历史报告；不读取 Git/Obsidian 正文，也不接入后续 P2 自动成果证据。现有“智能目标”与娱乐边界仍按旧口径运作，不作为用户承诺。

## 数据与证据

目标派生状态保存在 `AppPaths.intelligence_dir/daily_goals_v1.json`，以日期为键，每日最多 3 项。每项有稳定 ID、类型、标题、关联对象、目标分钟数（仅时间目标）、人工成果确认及确认时间。使用文件锁、原子替换、修订号和恢复日志；损坏时停止写入并保留文件。不得存储 API Key、网页正文或额外的原始标题。

时间目标只能关联人工确认的 V1.6 任务，或工作类分类。实际投入使用规范数据库会话中的 `attention-v1` 主动参与秒数：严格校验会话、去重，任务只纳入人工明确归属的会话，分类纳入对应分类。无记录或口径异常时显示“证据不足”，不能填成 0；有可信记录但目标类别无记录时可显示 0。差值为目标秒数减已可信投入秒数，不把达到时长视为成果完成。

成果目标只接受用户手动确认，不自动依据软件打开时间判定。界面与周报明确标注“用户确认”，不称为 Git/笔记独立核实。撤销确认保留可操作性。云端 AI 不参与目标设定、成果判定或时间计算，因此离线与预算状态不影响 V1.7 本地功能。

## 界面与报告

今日概览新增紧凑“今日计划”卡，最多展示 3 项、各自计划/实际/差值或用户确认状态；入口进入现有统计页的“目标”标签。目标页允许选日期、增删改目标、确认/撤销成果，并显示来源与缺口原因。所有输入使用纯文本显示，长标题省略但可查看完整内容。

现有周报生成流程追加“计划 / 投入 / 已确认成果”小节：按 ISO 周聚合已设置目标的日期，一次只读查询这一周会话；时间目标分项列计划、可信投入和差值，成果目标列用户确认状态。未设置目标、缺少可比较会话或旧口径时明确提示。旧周报主体与现有日报/月报不重算、不覆盖历史文件；只有重新生成的周报包含新小节。

## 验收与回退

先用合成会话验证 3 项上限、修订冲突与恢复、旧版本/异常/重复会话门控、任务人工归属、分类统计守恒、成果手动确认与撤销、ISO 周边界和周报文案。再执行全量测试、`compileall`、GUI smoke、隔离发布版 smoke。关闭/不使用目标功能时旧服务不受影响；回退程序不需要迁移或回滚 SQLite。
