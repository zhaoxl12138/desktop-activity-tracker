# 工作干扰分析卡设计

## 目标

用“工作干扰分析”替换首页“今日专注时间轴”，回答今天的工作主要被什么打断；保留下方“关键工作片段”，不重复工作节奏卡的累计曲线或时间分布卡的分类占比。

## 范围

- 替换左侧下方卡片中的 24 小时时间轴与图例；关键工作片段列表继续保留。
- 新增首页快照字段 `interruption_analysis`，只基于已读取的当天会话计算。
- 不新增数据库表、不迁移或改写历史数据、不增加逐日或逐条数据库查询。

## 统计口径

一次可分析干扰是：工作学习会话后出现至少一个非工作会话，并在 15 分钟内重新进入工作学习。

- 连续的非工作会话合并为一次干扰；同一过程中的多个子进程不重复计数。
- 干扰时长是离开工作至重新进入工作的已记录时长，不命名为“效率损失”或“恢复成本”。
- 社交通讯、娱乐休闲、普通浏览器、其他应用和系统空闲均可作为来源；系统空闲在界面中显示为“离开电脑”。
- 超过 15 分钟才回到工作、记录缺口、程序停止和损坏会话均不算干扰；它们不影响干扰次数和时长。
- 来源优先使用应用显示名；浏览器在有安全的规范化标题时追加简短标题，否则只显示应用名。

## 卡片界面

卡片标题为“工作干扰分析”，高度沿用现有专注卡区域。

1. 顶部结论：`今天被打断 8 次，主要来自 微信`；无有效干扰时显示“今天暂未识别到可分析的工作干扰”。
2. 三项摘要：明显干扰、离开工作、主要来源。
3. 来源排行：最多展示 3 个来源，每行显示来源名、次数和时长；社交用蓝色、娱乐用橙色、系统空闲用灰色、其他用中性蓝灰。
4. 下方的“关键工作片段”维持现有阈值（超过 5 分钟）、主题、应用和时长样式。

## 数据模型

`interruption_analysis`：

```python
{
    "status": "ready" | "empty" | "unavailable",
    "total_count": int,
    "total_seconds": int,
    "primary_source": {"label": str, "count": int, "seconds": int, "kind": str} | None,
    "sources": [
        {"label": str, "count": int, "seconds": int, "kind": str}
    ],
}
```

其中 `sources` 按次数、时长、名称排序并截断到前三名。数据库查询失败时，状态为 `unavailable`，不输出误导性的零值。

## 验收

- 工作 → 微信 → 工作被合并为一条微信干扰。
- 工作 → 微信 → 浏览器 → 工作只计一次，来源取干扰期间累计时长最多的来源。
- 超过 15 分钟、数据缺口、损坏会话和程序停止均不计入。
- 无干扰、无工作、查询失败均有明确降级文案。
- 首页无“今日专注时间轴”及其 24 小时刻度、图例。
- 关键工作片段仍显示，1280×720 与更大窗口无重叠和裁切。
- 复用首页范围会话读取；性能测试确认没有额外数据库查询。
