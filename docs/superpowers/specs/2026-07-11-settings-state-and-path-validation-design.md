# DayLens 设置状态与路径校验修复设计

## 目标

修复设置保存后运行中组件仍使用旧配置、数据库浏览按钮选择错误对象、无效数据库路径缺少友好反馈，以及启动项创建失败后配置状态与实际状态不一致的问题。

## 设置状态传播

`SettingsPage` 保存成功后发出包含完整新配置的信号。`MainWindow` 接收后更新自身配置，并把新的 Obsidian 输出路径同步给报告页和托盘管理器。worker 仍由设置页调用现有热更新接口处理采样间隔、空闲阈值和分类器。

数据库路径变化时，设置页先发出新配置，再发出重启请求。当前进程不会尝试动态切换数据库连接，避免采集线程、页面查询和托盘统计落到不同数据库。

## 数据库文件选择与校验

数据库路径的浏览按钮使用文件保存选择器，过滤 `.db` 文件，并允许用户选择已有文件或输入新文件名。报告和 Obsidian 路径继续使用目录选择器。

保存前要求数据库路径非空。持久层先规范化路径、创建父目录并初始化 SQLite 结构；失败时不得覆盖 `config.yaml`，设置页显示错误并保持当前采集运行。

## 启动项状态一致性

启动项切换函数返回实际结果。快捷方式创建失败或找不到可执行文件时，复选框恢复为未启用，并使用恢复后的实际值写入配置。禁用启动项时删除快捷方式；不存在视为成功。

## 错误处理

设置保存和快捷方式操作在设置页统一捕获异常，通过警告对话框显示原因。保存失败时不触发热更新或重启，也不显示成功信息。

## 测试

1. 设置页保存成功后发出新配置，数据库路径变化时按顺序发出配置与重启信号。
2. 主窗口接收新配置后更新报告页和托盘使用的 Obsidian 路径。
3. 数据库浏览按钮调用文件选择器，其他路径调用目录选择器。
4. 空数据库路径和不可用路径不会覆盖现有配置。
5. 启动项创建失败时最终保存值为未启用。
6. 完整 pytest、源码编译、PyInstaller 构建、快捷方式刷新和运行进程路径验证全部通过。

## 范围外事项

本批不迁移旧数据库数据、不改变报告目录结构、不新增设置字段，也不重构托盘或主窗口的整体生命周期。
