# 首页卡片职责优化设计

## 目标

在不新增数据库、不迁移表结构、不改写历史记录的前提下，进一步减少首页信息重复，让四张卡分别回答一个问题：今天推进了什么、数据是否可信、使用了哪些应用、时间由什么构成。

## 关键工作片段

“今日关键 Session”改为“关键工作片段”。只消费工作学习类会话；相邻工作会话间隔不超过 30 秒时视为同一片段，因此 Codex 与 Chrome 学习页面之间的短暂切换不会拆碎工作。片段显示时间范围、代表性主题、参与时长和涉及应用，按参与时长排序，默认展示最重要的五段。旧 `sessions` 快照仍保留，新增稳定字段 `work_episode_rows`。

主题优先选择片段内时长最长且不是应用通用名称的规范化标题；没有可靠主题时回退为主要应用组合。参与口径使用 `engaged_seconds`；旧快照缺少该字段时显式回退有效时长，不伪称参与。

## 数据可信卡

高、中可信洞察继续保留标题、证据和行动建议。低可信、数据健康或没有洞察时压缩为单行状态卡，只保留简短状态和一条原因，隐藏行动建议，避免通用提醒长期占用右侧首屏空间。所有动态文字使用纯文本渲染。

## 软件使用排行榜

排行榜按稳定应用身份聚合，而不是按展示名聚合：进程名做 NFKC、去空白、大小写和 `.exe` 后缀归一，同一应用别名合并；Chrome 与 360ChromeX 等不同应用始终分开。每行保留明确应用名，并显示主要用途、前台时长以及参与/被动构成；用途来自该应用已聚合的窗口标题，仅作展示，不改变分类或历史数据。

排行榜主排序仍为前台有效时长，以确保被动视频等应用不会消失；参与和被动时长作为次级口径展示。旧三元组 UI 输入继续兼容一个周期。

## 时间分布

删除底部“较昨日”分类比较行，时间分布卡只保留参与/被动媒体/挂机状态、注意力圆环和分类构成。昨日及历史节奏比较统一由“工作节奏对比”负责。`day_comparison` 继续保留在快照中供兼容消费者使用，但新卡片不再消费。

## 兼容、降级与验收

- 首页保留 `session_top3_widget`、`trend_card` 等现有属性别名。
- 缺少 `work_episode_rows` 的旧快照可在 UI 端从 `sessions` 构建兼容片段。
- 损坏时间或负数计时的会话不进入工作片段和排行榜明细。
- 1280×720 下不横向滚动、不重叠、不裁切。
- 完成服务层、组件层、首页接线、全量测试、GUI smoke、`compileall`、差异检查和发布构建。
