# DayLens 隐藏缺陷修复设计

## 目标

修复全局审计中已经复现的统计准确性和展示一致性问题，同时保持唯一数据库、现有计时口径和历史原始记录不变。

## 方案选择

### 方案 A：边界修复与兼容聚合（采用）

- 英文短关键词按字母数字词边界匹配；中文、域名、带标点产品名继续使用包含匹配。
- 消除 OBS 在“创作工具”和“娱乐休闲”之间的归属冲突，固定归为创作工具。
- 时间分布前三行保持固定，第四行在浏览器、系统工具和真正的“其他”中选择累计时长最大的分类，确保所有有效时间都有展示归属。
- 近7天改为包含今天的连续7个日期；今日节奏不再按分类版本过滤同日会话，只用同一颜色展示。
- 日报先按展示大类聚合，再生成单行统计；“最长使用软件”始终显示软件名。
- 增加按日轮转的本地日志，捕获 Python 未处理异常、Qt 消息与关键后台错误。

优点是改动集中、兼容现有数据库和 UI 模型，能直接消除已复现错误。缺点是关键词边界规则需要回归验证域名、缩写和中英文混排。

### 方案 B：把所有关键词改成正则表达式

表达能力最强，但会显著提高规则维护成本，用户自定义关键词也容易写出无效或高开销正则，本次不采用。

### 方案 C：引入分类置信度与人工确认

长期效果更好，但需要数据库字段、交互和历史迁移，超出本轮修复范围，本次不采用。

## 分类匹配

新增统一关键词匹配函数：纯 ASCII 字母数字关键词必须满足两侧不是 ASCII 字母或数字；包含中文、点号、斜线、连字符或空格的关键词沿用大小写无关包含匹配。这样 `Anki` 不再命中 `Ranking`，`CAN` 不再命中 `American`，但 `youtube.com`、`ChatGPT`、`RK3568` 等既有规则继续生效。

OBS 的进程和标题关键词只归入 `creative`，不再进入 `video`，计时策略保持主动参与。

## 首页统计

时间分布以 `effective_seconds` 为总分母。前三行固定为工作学习、娱乐休闲、社交通讯；第四行从浏览器、系统工具、其他中选择当天累计最长者。未被第四行选中的残余分类不丢失：统一累加到第四行，确保各行秒数之和等于有效时间；若存在多个非零残余分类，标签使用“领先分类名称 + 等”（例如“浏览器等”），避免把合计时长误称为单一分类。

近7天窗口为今天及之前6天，横轴显示7个日期。今日节奏使用当天全部可信 `attention-v1` 会话，不按 `classification_version` 切断；分类版本变化只影响比较状态，不影响今日累计曲线、首次参与和最长连续等事实指标。

## 报表

日报分类统计按四个展示大类聚合，工作类只输出一行。环比、Top 应用和 Top 内容与聚合后的分类键集合一起计算。“最长使用软件”只使用进程的展示名称，不再用窗口标题替代。

历史8月22日至24日的12条误分类会话不在代码修复中自动改写。代码验证完成后另做精确、可回滚的数据修正，并重新生成受影响日报、周报和月报。

## 运行日志

在 GUI 启动最早阶段配置轮转文件日志，路径固定为 `data/logs/daylens.log`。记录启动、退出、未处理异常、Qt 消息、工作线程致命错误与数据库路径；限制文件数量和大小，避免无限增长。日志失败不得阻断记录功能。

## 测试与验收

- 分类回归：Ranking/Anki、American/CAN、教程视频、域名、OBS。
- 时间分布守恒：包含真实 other，四行之和等于有效时间。
- 近7天：包含今天并显示连续7个日期。
- 今日节奏：同日多个分类版本全部计入事实指标，比较仍标记口径变化。
- 日报：工作学习只出现一行，最长软件显示应用名。
- 日志：未处理异常可写入轮转日志，日志初始化失败时应用仍可启动。
- 完成定向测试、全量测试、compileall、数据库 quick_check、GUI smoke、发布构建和发布版运行观察。

## 非目标

- 不新增数据库，不迁移表结构。
- 不改变音频、GPU、网络视频检测算法。
- 不修改时间分布以外的首页布局。
- 不在代码提交中静默改写历史记录。
