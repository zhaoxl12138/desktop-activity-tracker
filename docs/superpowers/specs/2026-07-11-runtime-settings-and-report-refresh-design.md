# DayLens 运行时设置与报告刷新修复设计

## 目标

修复三个运行时问题：数据库路径修改后仍使用旧连接、当前周期周报/月报生成后长期不更新、清空 Obsidian 输出路径后旧覆盖值在重启时恢复。同时恢复当前用户的 Obsidian 输出目录为“桌面活动日报”根目录。

## 数据库路径变更

设置保存前比较当前有效数据库路径与用户输入的新路径。路径未变化时继续热更新采样间隔、空闲阈值和分类器。路径变化时先正常保存配置，然后请求应用执行受控重启。

受控重启必须先停止 worker，等待当前会话刷新和数据库连接关闭，再用当前 Python 启动方式或冻结版可执行文件启动新进程，最后退出旧进程。重启失败时保留旧进程并向用户显示错误，避免采集静默中断。

数据库路径使用规范化后的绝对路径比较，避免仅因大小写、分隔符或相对路径形式不同而误触发重启。

## 当前周期报告刷新

周报和月报继续在启动后及每五分钟检查。当前周期的报告允许覆盖生成，使内容随本周、本月新增数据更新，不再以“文件存在”作为停止更新的条件。

生成仍复用现有导出函数和固定文件名，因此不会产生重复文件。单次生成失败只记录错误，不影响采集和其他报告。现有五分钟调度天然限制写入频率，不增加额外后台循环。

## Obsidian 路径清除

持久用户配置保存接口支持显式删除键。设置页保存空的 Obsidian 路径时，从 `data/user_config.yaml` 删除 `obsidian_output_path`，而不是跳过该字段。之后加载配置时不会再由旧值覆盖 `config.yaml`。

本机当前路径从固定的 `2026/2026-06` 恢复为“桌面活动日报”根目录。报告同步仍沿用现有复制行为，本次不扩展目录结构策略。

## 测试

采用测试驱动实现：

1. 增加设置持久化测试，证明清空 Obsidian 路径会删除旧覆盖值。
2. 增加设置页行为测试，证明数据库路径变化触发受控重启，而普通设置变化只热更新。
3. 增加报告调度测试，证明已有当前周报/月报仍会被刷新。
4. 运行完整 pytest、Python 编译检查和发布构建。
5. 发布成功后刷新桌面及启动项快捷方式，启动新构建并确认运行路径指向 `release/DayLens.exe`。

## 范围外事项

本次不实现数据库数据迁移、不改变 Obsidian 报告目录层级、不重构全部 GUI 生命周期，也不处理与这三个问题无关的代码清理。
