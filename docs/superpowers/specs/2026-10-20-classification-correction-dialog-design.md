# DayLens 分类纠错对话框修复设计

## 目标

修复实时监控中的两个分类纠错入口：

- “纠正当前分类”能够稳定选择完整分类、保存，并给出明确反馈。
- “管理已确认模式”除启用、停用和删除外，可以直接修改模式分类。
- 两个入口使用同一套 DayLens 深色对话框和分类选项，避免系统 `QInputDialog` 的样式、可操作性和选项不一致问题。

## 交互设计

新增一个应用内分类选择对话框。对话框显示：

- 当前应用名称。
- 当前窗口标题或模式示例。
- 当前分类。
- 完整分类下拉列表。
- “取消”和“保存分类”按钮。

完整分类列表包含技术学习/开发、阅读学习、办公/求职、AI工具、设计创作、社交通讯、系统工具、游戏娱乐、影音娱乐、浏览器和其他。默认选中当前分类；保存相同分类时允许关闭，但不重复写文件。

保存成功后在原页面显示短暂状态反馈；失败时展示具体错误信息，不再吞掉异常后只显示笼统文案。

## 当前标题纠错

“纠正当前分类”读取最新前台样本并打开统一对话框。确认后：

1. 写入精确标题人工纠错。
2. 标题信息足够时同步生成同应用相似标题模式。
3. 通知记录线程重新加载智能分类。
4. 只影响确认后的采样，不改写历史数据。

影音分类不再被入口直接拦截。对话框会提示“影音分类可能影响后续被动播放计时”，但用户明确保存后允许生效；现有音频、GPU和暂停检测逻辑不变。

没有前台样本时按钮保持可用但显示“暂无可纠正的前台记录”，不再静默无响应。

## 已确认模式管理

保留模式选择步骤，选中模式后提供：

- 修改分类。
- 启用或停用。
- 删除。

“修改分类”打开同一个分类选择对话框，默认选中模式当前分类。保存时原地更新该模式的分类，保留模式 ID、创建时间、命中次数、最近命中时间、启用状态和示例；不创建重复模式。

删除仍使用确认提示，避免误删。所有操作完成后刷新分类器并显示结果反馈。

## 代码边界

- 新建独立对话框组件，避免把更多交互逻辑堆进 `LiveMonitorPage`。
- 在智能证据服务中新增按模式 ID 更新分类的原子操作。
- 分类选项集中定义，当前标题纠错、待确认列表和模式管理共用，防止入口间再次缺项。
- 不新增数据库，不迁移表结构，不改写历史记录，不改变唯一数据目录。

## 错误处理

- 模式在打开后被删除：提示“模式已不存在”并刷新列表。
- 分类非法或文件写入失败：不改变现有文件，显示具体失败原因。
- 相似模式无法从短标题生成：仍保留精确标题纠错，并在成功反馈中说明只保存了当前标题。
- 分类器重载失败不撤销已成功写入的数据，但明确提示需要重启后生效。

## 测试与验收

- 对话框默认选中当前分类，完整分类均可选择。
- 点击取消不写入任何文件。
- 当前标题纠错成功生成精确纠错；可形成模式时同时生成模式。
- 无采样时给出可见反馈。
- 模式分类修改为原地更新，不改变模式 ID 和统计字段。
- 模式启停、删除继续有效，删除需要确认。
- 两个入口保存后都发出分类重载信号。
- 深色和浅色模式下文字、下拉列表及按钮均清晰可见。
- 完成定向测试、全量测试、`compileall`、GUI smoke，并在发布版中实际模拟两个入口。
