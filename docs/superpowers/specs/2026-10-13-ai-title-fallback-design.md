# DayLens AI 标题兜底分类设计

## 目标

规则无法识别的窗口标题不再被无条件视为“其他”。DayLens 在本地规则之后增加一个受预算约束的 DeepSeek 兜底层，并明确区分“待识别”“待确认”和“已由 AI 高置信度归类”。

## 决策顺序

1. 用户手动纠正优先级最高，并永久本地复用。
2. 明确命中的本地规则直接生效，不发送给 DeepSeek。
3. 仅 `browser_general` 和 `other` 两类规则兜底标题进入 AI 候选。
4. 候选标题在主动参与累计达到 30 秒后进入最多 5 条的批量请求；每天最多 30 个新标题，沿用每月预算上限。
5. 相同“进程名 + 完整标题 + 分类规则版本”只请求一次，后续使用本地缓存。

## AI 结果应用

- `high`：允许落入 `coding`、`reading`、`office`、`ai_tools`、`creative`、`social`、`tools`、`gaming`、`video`。
- `high + video`：只改变内容分类；时长仍由既有前台窗口、播放状态、音频/GPU/网络等视频检测链路决定，暂停或离开不能因为 AI 分类而持续计时。
- `high + gaming`：采用游戏分类的主动参与规则，不允许无交互无限累计。
- `high + browser_general/other`：仍视为无法确定，不把“其他”伪装成可靠结论。
- `medium/low/conflict`：不改变统计分类，界面显示“AI 待确认”，等待用户纠正；不重复请求同一标题。

## 显示语义

- 开启智能分类且标题处于规则兜底、尚无缓存：分类详情显示“AI 待识别”。
- 已有中低置信度结果：显示“AI 待确认”，同时展示建议分类、置信度和简短原因。
- 高置信度结果实际生效：显示来源“AI”，并从结果返回后的下一段会话开始计入新分类；不改写已落库历史时间。
- 未启用智能分类或无密钥时，维持现有本地分类显示，不制造“AI 待识别”状态。

## 安全与隐私

- 只发送脱敏后的进程名和窗口标题，不发送 URL、文件内容、键盘输入、截图或历史数据库。
- API Key 继续只存 Windows 凭据管理器。
- AI 结果必须属于允许分类、引用当前请求 ID 且通过结构校验；异常时继续使用本地分类。
- 手动纠正立即覆盖 AI 缓存，但不批量改写历史记录。

## 兼容与迁移

- 不新增数据库、不迁移表结构、不改写历史会话。
- 现有 `classification_cache.json` 继续兼容；由于应用范围扩大，历史缓存中的高置信度 `video/gaming` 可直接生效。
- 不改变日报、周报、月报和现有预算文件格式。

## 验收

- 未知标题在启用 AI 时显示待识别状态，而不是看似确定的“其他”。
- 高置信度工作、社交、工具、游戏、视频结果均能前瞻性生效。
- AI 视频分类仍受播放状态控制，静音暂停或离开不误计。
- 中低置信度结果不改变统计，只显示待确认及原因。
- 明确本地规则、手动纠正、无密钥、预算不足和 API 失败均保持原有安全降级。
- 同标题不重复请求；现有每日 30 标题和月预算约束不变。
- 通过定向测试、全量测试、`compileall`、发布构建与运行版 smoke。
