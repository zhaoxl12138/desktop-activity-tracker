### 已确认的具体问题

1. 日报会话明细使用 `max(1, eff // 60)`，10 秒会被显示为 1 分钟，0 秒也会成为 1 分钟。
2. 日报“效率评分”实际由工作类别有效占比和娱乐超过固定阈值的扣分组成，不能代表工作质量。周/月摘要同样存在等级评价。
3. `_query_peak_hours()` 将整段有效秒数归到开始小时，且统计不限工作类；摘要却称为“最专注时段”。
4. 周/月主统计读取混合历史聚合，但 `_query_prev_period()`、最佳日、部分排行等直接查询 `activity_sessions`，无法保证与包含旧日志的主统计一致。
5. 报告中心目前只显示元信息，没有正文预览、全文查找或目录导航。
6. 报告中心的 `_generate()` 直接在 GUI 线程执行生成与同步；主窗口其他报告任务已经有后台队列，可以复用。
7. 日报元信息将 23:00 描述为固定截点，但日报导出没有按 23:00 裁切查询；调度触发时刻不能等同于数据截止。
8. 计划/投入/成果目前只在周报有独立小节，日报和月报不能直接套用现有文本。

## 2. 方案比较与推荐

- **推荐：原生报告 V2 + Qt 只读预览。** 保留 Markdown 文件作为统一交付物，数据模型、渲染和预览分层；不新增运行时依赖，无 Key 也可使用。
- 仅增加预览：改动最小，但错误时长、评分和重复统计仍存在，不满足本轮“报告体验”目标。
- WebView/HTML 报告中心：视觉自由度高，但增加打包、资源加载、安全和维护成本，本期不采用。

## 3. 产品结构与默认展示

### 日报正文

1. **报告范围与状态**：日期、生成时刻、最后记录时刻、当天是否仍在累计；可信度只保留一行。
2. **关键发现**：最多三条本地事实，优先目标偏差、主要时间去向、有可比证据的变化。每条关联本地事实 ID，不强行凑足三条。
3. **时间概览**：有效活动、工作主动参与、娱乐有效活动、用户已确认成果数。混合旧记录必须说明已知部分，未知分项不能补零伪装完整值。
4. **目标与成果**：计划、可信投入、时间目标差额、成果是否由用户确认分开显示。没有目标显示一行空状态。
5. **下一步建议**：最多一条，优先依据用户已设目标或娱乐边界；没有充分依据时不生成建议，不默认要求用户减少娱乐或增加工作。
6. **详细数据与口径**：软件排行、分类统计、原会话时间线、30 分钟分桶及来源说明后置为附录，不删除原始记录。
7. **已有 AI 智能汇总**：继续使用既有安全附录，默认不重新生成；预览可直接跳转。

### 周报与月报

- 使用相同的“关键发现 → 时间概览 → 目标与成果 → 至多一条建议 → 详细附录”顺序。
- 周报保留每日分布；月报保留每日分布/热力信息，但移出正文重点区域。
- “最专注的一天”改为“工作参与最多的一天”；“时间黑洞”改为“娱乐使用最多”；取消 A/B/C 等级、优秀/需改进和“合理/偏高”等无用户目标依据的评价。
- 目标与成果按现有 `evaluate_day()` 语义逐日汇总；不重新启用任务链，不把达到时长视为成果完成。
- 数据不足路径生成同结构的简洁报告，区分“没有活动记录”“缺少可用计量证据”“对比不可用”，不恢复已下线的画像诊断段落。

### 不是新增 AI 功能

关键发现和建议先由确定性本地规则生成。原有 AI 只作为可选附录；不改变模型响应字段，不为每次预览或每条建议发请求。本轮不重新开发行为画像、任务链、目标模板、历史搜索、分类调整中心或 Ask DayLens。

## 4. 计量与结论规则

### 时长

- 有效活动沿用现有聚合 `effective_seconds`，不重新计时。
- 主动参与、被动活动只展示现有可信分项；旧记录的有效活动不反推为主动参与或被动观看。
- 正文“工作主动参与”使用 `work_engaged_seconds`；“工作类别有效活动”若保留在附录，必须使用不同名称。二者不能共用含糊的“工作时间”。
- 娱乐沿用现有娱乐类别的有效活动口径，包含已确认被动视频时间。
- 分类占比以类别有效活动 / 全部有效活动为分母，名称明确为“有效活动占比”。不将其包装成效率评分。
- 原始秒数参与求和。会话行使用精确到秒的报告格式；0、1、59、60、61 秒分别保持准确，不最低补一分钟。全局 `fmt_seconds()` 和其他页面无需一并更改。
- 空闲与未观测缺口分开，覆盖天数不等于全天覆盖。任何被隐藏的图表事件也不能从报告总量中删除。

### 时段与趋势

- 本期不在正文输出“最专注时段”或推断认知状态。原有 30 分钟分桶可留附录，并明确是按会话统计分配的估计，不代表精确输入发生时刻。
- 趋势先对两侧调用 `assess_range()` 和 `compare_ranges()`。总参与可比、分类不可比时只展示允许比较的指标；不可比不输出增减百分比。
- 当前周/月正文总量仍包括截至读取时的已记录数据，标记“进行中”；趋势优先比较已完成日期，不拿进行中的今天与完整上一天比较。
- 当前周：本周截至昨天的相同星期范围，对照上周对应范围。月中：本月截至昨天与上月对应已完成日期范围比较，遇到短月用双方都存在的日期数并写明范围。完整周期按完整周期比较，显示周期天数和记录天数。
- 无记录日不自动解释成零投入；数据不足时保留总量和覆盖信息，抑制趋势结论。
- 历史日报按所选日期生成；23:00 是调度触发时间，不是数据库过滤截点。元信息写实际读取截止和最后记录时间，不声称未实际执行的裁切。

### 报告上下文

`ReportContext` 至少包含：

- `format_version`、`kind`、周期标识、请求日期、实际观察日期及截止时刻。
- 现有混合历史聚合结果、可信计量分项、覆盖与比较判定。
- 目标逐日评估和用户已确认成果；旧任务目标只按现有兼容逻辑读，不新增任务分析。
- `facts`、`observations`、至多一个 `action`，观察与建议只引用已有事实 ID。
- 附录数据、原生证据指纹、已有 AI 附录状态。

查询和聚合在后台完成；正文渲染不追加查询。优先将当前范围与比较范围合为一次批量读取，再用现有聚合函数按范围取子集；复用已有混合历史去重和可信度逻辑，不另写一套。报告读取使用短生命周期只读事务，保证同一报告的主统计、排行和证据来自同一 SQLite 快照；不跨线程共享连接，不在持有数据库事务时渲染 Markdown、访问网络或写报告文件。

单次数据加载后，软件排行从未截断聚合结果产生，不能从公开接口已截成前 20 条的软件列表反算类别总量。按需提供仓储适配器复用聚合内核，不复制 SQL 或计量规则。

目标 JSON 不与 SQLite 事务强行锁成一个全局事务：读取其 revision 并纳入原生上下文，若读取期间 revision 变化，有限重试一次，否则标记目标暂不可用，不阻止原生报告。

## 6. 内置 Markdown 预览

### 布局

- 宽窗口使用可拖动 `QSplitter`：左侧约 30% 报告列表、右侧约 70% 正文；不再用固定宽度元信息侧栏。
- 内容区逻辑宽度低于 1000 时切换“列表 / 预览”视图，提供返回列表，避免 1280x720 在 150% DPI 下两栏挤压。
- 顶部保留三类报告生成按钮和目录入口，窄屏分两行；打开、下载、同步收敛为预览工具栏。
- 单选立即预览，多选恢复批量下载摘要，不在多个报告之间随机选择正文。原每页 50 份和每种报告页码独立保存逻辑保持。
- 小节目录默认折叠为下拉列表，点击定位；Ctrl+F 打开报告内查找，支持上一个/下一个及无匹配提示。

### 异步与缓存

- 选择只读本地文件，不生成报告、不查全年会话、不调用 AI。
- 缓存键使用规范路径、`mtime_ns`、大小；默认最多 8 份、合计最多 4 MiB，淘汰最久未用项。窗口标题不是缓存身份。
- 文件读取在后台进行，加载携带请求序号；快速切换、切页、切报告类型和关闭页面后，旧结果不得覆盖新选择。
- 刷新后检查精确纳秒时间和大小；读取前后身份发生变化时重试一次，仍变化则保留旧视图并提示更新中。不对每次点击重读同一文件或重查数据库。
- 2 MiB 以上的报告不直接全量富文本渲染，提供明确“文件较大”的有限文本预览和外部打开；原文件及下载内容完整保留，不静默截断导出。
- 文件丢失、权限错误、编码损坏显示可重试状态，不清空其他报告或自动新建文件。
- 报告中心的手动生成改为提交到已有 `BackgroundTaskQueue`，用周期/路径身份去重；不能让低优先级预览排在耗时补报或网络汇总之后，预览使用独立有界只读工作器。

### 安全

- 使用 `MarkdownNoHTML`，不执行或信任窗口标题、目标名和模型文字中的 HTML。
- 新原生 Markdown 的标题、表格单元格和路径统一转义，保留文字，不让 `|`、换行或 HTML 注入报告结构。
- 覆盖 `loadResource()`，默认拒绝图片和外部资源自动加载，包括 `http(s)`、`file`、UNC 和相对路径；预览不产生隐式联网或读取其他本地文件。
- `setOpenLinks(False)` 与 `setOpenExternalLinks(False)`；内部目录跳转由自己处理，外链只在明确点击且确认后按白名单打开，拒绝其他协议。
- 旧报告和 AI 附录只读渲染，不因安全清理修改源文件。原 AI 附录继续作为字面量文本显示。

## 7. AI 状态、证据和历史兼容

- 预览状态由纯读取接口获得，不能调用 `generate_budget_review()` 充当查询；现有生成接口会检查开关和 Key，不适合离线预览旧汇总。
- 区分“没有 AI 附录”“证据一致”“基于旧数据”“旧汇总无法验证”“当前无法验证”。指纹计算失败不能误报为最新，也不阻止打开报告。
- 原生文档的格式版本与计量版本分开。`report-v2` 只标识模板，不影响计量和分类可比性。
- 新原生报告在非可见元信息中记录报告范围与原生证据身份；目标确认变化影响原生目标小节的 freshness，不假装它一定属于旧 AI 请求的输入。
- AI freshness 只与该 AI 汇总实际使用的事实、周期、隐私及提示版本关联。不能仅因最新缓存 JSON 变化就认定文件中旧附录已更新；没有附录身份对应信息的旧报告标为“无法验证”。
- 周/月 AI 目前来自下级摘要，不把它描述为直接分析全部原始会话。父级引用已过期摘要时标记依据过期，不在查看时递归补请求。
- 不为 V2 自动批量生成或重写既有历史报告。既有当前报告由原有刷新/手动生成路径更新时保留其 AI 标记区；历史缺失文件仍可按现有补报流程新建。
- 新正文只使用原有本地事实，不新增 API 数据字段，不上传正文或原始会话库；月预算、每日限制、密钥管理和隐私过滤保持。
- 手动更新原生报告与重新调用 AI 是两个独立操作。后者必须沿用已有主动确认和预算检查，不因生成 V2 自动触发。
- CSV 导出格式、Obsidian 年/月路径、原有文件名和下载行为保持，便于回退和外部工具继续读取。

## 9. 完成标准
