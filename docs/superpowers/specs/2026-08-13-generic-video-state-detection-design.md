# 通用视频播放状态检测设计

## 目标

让所有被分类为视频的前台应用统一使用进程树音频检测，避免主进程无音频会话、子进程实际输出声音时被误判为静音空闲。

## 方案

`AudioDetector.is_playing(pid)` 保留现有峰值阈值、缓存周期和全局音频兜底，但查询顺序改为：当前进程及其递归子进程的音频会话 → 全局音频会话兜底 → 异常时按播放处理。进程树查询失败时不影响全局兜底；权限、进程退出和音频会话异常均按连续性优先处理。

计时器仍只对前台且已分类为 `video` 的会话调用检测器。键鼠空闲不会被音频检测重置；有音频时进入 passive，无音频且超过现有阈值时才进入 idle/自动收尾。网络流量和 GPU 活动保留为后续可插拔辅助信号，本次不让它们直接改变历史口径。

## 验收

- 主进程峰值为 0、子进程峰值大于阈值时返回播放。
- 主进程无会话但子进程有会话时返回播放。
- 无目标会话时仍保留全局音频兜底。
- 进程树或音频 API 异常时不截断视频计时。
- 不增加数据库表、不迁移历史记录，发布版继续使用现有唯一数据库。
