# 自动智能汇总与预算输入框修复

## 已确认需求

- 修复预算输入框白底白字，不改变预算数值或计费逻辑。
- 每天当地时间 23:00 生成日报智能汇总；周日 23:00 生成周报；月末最后一天 23:00 生成月报。
- 同一时点依次处理日报、周报、月报。软件未运行时，下次启动补生成。
- 智能内容直接进入现有日报、周报、月报文件，移除独立“生成 / 查看智能复盘”栏。
- 沿用唯一规范数据库、现有报告目录和统一月预算。

## 方案选择

采用软件内现有后台报告队列与定时检查，不创建 Codex 自动化或 Windows 独立任务。不要求电脑关机时运行，不新增常驻进程。相比独立报告文件，原报告内的固定智能汇总章节更符合现有查看、下载、同步流程。

## 实现边界

### 输入框

把 QDoubleSpinBox 纳入通用输入样式，明确背景、文字、选中与焦点状态；检查深浅主题及 1280×720 布局。

### 调度与补生成

- 周期采用本机当地日期，同次检查只捕获一次 now。
- 保存自动汇总启用起点，只补启用后的到期周期，不追溯所有历史月份，避免突然消费。
- 23:00 的当日报告明确标注截至生成时刻；该周期不再调用 AI 更新，之后原生统计更新不抹掉此章节。
- 启动或定时检查把未完成周期排队，按日期顺序以及日报、周报、月报依赖执行。
- 无记录的日期不请求 AI；未到期的当前周、当前月不提前生成 AI 汇总。
- 手工查看和重新导出报告复用已有智能结果，不触发第二次收费请求。

### 报告保留

- 对现有报告只附加有明确标记的“智能汇总”章节，不删除用户原有正文。
- 没有原生报告时先生成原生报告，再加入智能章节。
- 所有原生导出路径，包括小时刷新、手工生成及定时生成，都保留已存在的智能章节。
- 报告原子写入，串行化报告写操作，避免后台和手工导出互相覆盖。
- 原有查看、下载和 Obsidian 同步路径继续可用；不新增另一组 AI 报告列表。

### 费用与故障

- 沿用总开关、智能复盘开关、密钥存储、月预算与周期请求标记。
- 日报只发送脱敏的聚合事实；周报复用日报摘要；月报复用周报摘要并明确覆盖范围，跨月周不声称是精确月度总计。
- 请求发出前持久化周期标记；重启不能导致重复请求。
- 缺少密钥、开关关闭或预算不足不发请求；状态可见，不影响原生日报。
- 已发请求但超时或结果不确定时不自动重复扣费；保留失败状态。
- 多日补生成继续服从原有每日请求额度，剩余任务留待后续处理，不绕过省钱限制。

## 验收

- 23:00 前后、周日、月末、跨年 ISO 周、启动补生成、重复检查均有定向测试。
- 验证报告内容不被小时刷新或手动导出抹掉，重复执行不重复插入章节。
- 验证预算耗尽、无数据、无密钥、异常返回和重启后的幂等行为。
- 测试中使用模拟供应商，不消耗真实 API 额度。
- 全量测试、compileall、差异检查、GUI 样式检查、发布包 Qt 与凭据自检。
- 只在旧程序正常退出后替换原 release 路径；不强制结束记录进程、不改历史数据库。
