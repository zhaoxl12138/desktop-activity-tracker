# DayLens 人工分类纠错事务化设计

## 目标

让“人工纠错”符合用户对即时生效的预期。一次确认同时完成：

1. 保存同应用、同标题的人工分类决定，供后续采样复用。
2. 修正当天同进程、同规范标题的既有会话分类，使首页和统计立即变化。
3. 对普通桌面应用，将进程加入目标分类的本地规则，后续同应用直接命中。

本功能只改变分类归属，不改变任何计时数据、原始标题或历史日期范围。

## 已确认边界

- 历史修正范围固定为当天，不跨日。
- 历史匹配要求同一进程、同一规范标题；不因名称相似扩大范围。
- 普通桌面应用自动写入进程级本地规则。
- 通用浏览器不写入进程级分类规则，只保留精确标题与相似标题模式，避免整个浏览器被归为娱乐、学习等单一分类。
- 通用浏览器至少包括 Chrome、360ChromeX、Edge 和 Firefox 的常见进程名；判定集中在一个可测试函数中，不散落在界面代码。
- 用户选择的分类同时用于人工决定、当天匹配记录和普通应用的本地规则。

## 现状与根因

当前人工纠错只写入 `data/intelligence/manual_decisions.json` 和标题模式文件，界面也明确提示“只影响确认后的记录”。SQLite 中已经结束的会话不会被改写，本地规则也不会增加进程名。因此统计仍按会话落库时的旧分类聚合。

`Probably Stolen.exe` 的实际证据说明了该问题：当天 6 条会话、有效 2319 秒均在 16:02 前以 `other` 落库；人工决定在 16:09 保存，之后没有新的匹配会话，所以标题模式命中次数仍为 0，首页继续显示为“其他”。

## 架构

新增独立的分类纠错事务服务，GUI 不再分别操作人工状态、SQLite 会话和本地规则。服务接收：

- 数据库路径与智能状态目录。
- 进程名、原始标题、目标分类。
- 分类注册表与纠错范围。
- 当前本地日期，默认由服务获取，测试可注入。

服务返回结构化结果：

- 人工决定是否保存。
- 当天更新记录数。
- 是否新增或移动了进程规则。
- 是否属于浏览器例外。
- 时长守恒结果与审计路径。

## 数据流

### 1. 预检

- 校验目标分类存在且允许人工选择。
- 规范化进程名和标题；空值直接拒绝。
- 生成与现有人工决定一致的标题身份。
- 读取目标分类显示名和计时策略。
- 记录当天匹配记录的分类及时长汇总。

### 2. 普通桌面应用

- 在一个 SQLite 事务中，将进程名从其他分类的自定义进程列表中移除，并加入目标分类。
- 只更新当天、进程名不区分大小写且规范标题完全一致的会话。
- 更新字段限定为 `category_key`、`category_name`、`active_rule` 和 `classification_version`。
- 不更新 `duration_seconds`、`effective_seconds`、`engaged_seconds`、`passive_seconds`、`idle_seconds`、起止时间或原始标题。

### 3. 通用浏览器

- 不修改任何进程级本地规则。
- 仍更新当天同浏览器、同规范标题的会话分类。
- 保存现有精确标题决定和同应用相似标题模式，供后续相似页面复用。

### 4. 人工状态与一致性

SQLite 分类及规则更新成功后，再通过现有带文件锁和原子替换的状态服务保存人工决定。若文件写入失败，服务使用事务前快照恢复 SQLite 分类与规则；恢复失败则明确报错并保留审计证据，不显示成功。

人工状态写入成功后，触发工作线程重新加载智能决策和分类器。当前会话从确认点安全切分，确认前秒数不重新计算；已经落库且符合当天精确匹配条件的记录只改分类字段。

## 标题规范化

历史匹配复用采样落库时使用的规范标题逻辑，不能新造另一套宽松规则。比较前只执行既有、可逆的规范化，例如浏览器尾缀处理和空白统一；不使用模糊相似度，不读取网页正文或网址。

若旧记录缺少足以可靠比较的标题证据，则不修改该记录，只保留后续人工规则。

## 时长守恒与审计

更新前后对命中范围汇总以下字段并要求完全相等：

- `duration_seconds`
- `effective_seconds`
- `engaged_seconds`
- `passive_seconds`
- `idle_seconds`

审计文件写入 `data/logs`，包含日期、进程名、目标分类、更新数量、规则变更和时长汇总，不保存窗口标题正文。日志使用原子替换写入。

## 界面行为

- 纠错成功后显示：`已修正今天 N 条记录，并加入本地规则`。
- 浏览器显示：`已修正今天 N 条记录，并保存标题规则`。
- 若当天没有匹配记录，显示已保存后续规则，不误报历史修改。
- 成功后立即失效首页、分类统计和软件统计的缓存并刷新当前可见页面。
- 失败时保留原选择，显示具体错误，不显示部分成功。

## 测试

- 普通应用纠错会保存人工决定、修正当天精确匹配记录并加入本地规则。
- 同一进程的其他标题、前一天记录和其他进程不被修改。
- Chrome、360ChromeX、Edge、Firefox 只生成标题规则，不加入进程规则。
- 进程从旧分类规则移除后只存在于目标分类，重复纠错保持幂等。
- 纠错前后五类时长字段完全守恒。
- 状态文件写入失败时 SQLite 和本地规则恢复，不出现半成功。
- GUI 状态文字、缓存失效、工作线程智能决策和分类器热重载均正确。
- 完成定向测试、全量测试、`compileall`、GUI smoke、隔离发布版 smoke 和真实数据预览；真实应用前先备份数据库。

## 回退

- 程序回退不需要数据库迁移。
- 每次真实历史修正前创建 SQLite 备份；审计记录可定位本次变更。
- 人工决定和本地规则仍使用现有可编辑界面，可停用、删除或重新分类。
- 回退程序时保留当前数据库；如需撤销本次历史分类，可依据审计和备份仅恢复分类字段，不能覆盖修正后新增的其他用户数据。
