# DayLens 固定节拍采样设计

## 目标

消除记录线程“处理完成后再固定休眠一个采样周期”造成的长期计时损耗，同时不改变空闲判定、分类规则、Session 状态机、数据库结构和报告口径。

## 方案

记录线程使用 `time.monotonic()` 维护下一次采样截止时间。每轮采样结束后只休眠到该截止时间的剩余部分，而不是再次完整休眠一个采样周期。

- 正常处理耗时会从本轮休眠中扣除，使采样起点稳定在配置的固定周期上。
- 落后不满一个周期时允许下一轮立即执行一次，随后恢复正常节拍。
- 落后达到或超过一个完整周期时放弃追赶，把当前时刻作为新基准，防止连续补跑导致 CPU 升高。
- 暂停期间持续重置调度基准；恢复时立即采样，但不补算暂停时间。
- 设置热更新改变采样间隔后，重置调度基准，避免新旧周期相互影响。
- 停止和异常路径继续使用现有可中断休眠与统一清理机制。

## 非目标

- 不调整普通浏览器的分类口径；仍由标题规则决定是否进入工作学习。
- 不修改 60 秒空闲阈值或键鼠活动判定。
- 不把实际时间差写入 Session 计数器。
- 不修改 SQLite schema，也不修补历史记录。

## 风险控制

- 调度只决定下一次 `tick()` 的时间，不修改 `SessionTracker.tick()` 的输入与输出。
- 任何严重延迟最多触发一次立即采样，绝不循环追赶。
- 使用单调时钟，避免系统时间修改影响调度。
- 通过可注入时钟测试正常处理耗时、严重落后、暂停恢复和设置更新。

## 验收

- 模拟每轮有处理耗时时，下一次休眠只使用剩余周期。
- 严重落后时重新定基准，不产生负休眠或连续补跑。
- 暂停恢复和采样间隔更新不会追赶旧截止时间。
- 记录线程、Session、锁屏、数据质量和全量测试全部通过。
