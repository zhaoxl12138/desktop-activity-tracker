# DayLens 混合历史数据查询修复设计

## 目标

修复数据库同时包含新版 `activity_sessions` 和旧版 `activity_logs` 时，范围统计及娱乐趋势丢失旧日期数据的问题。

## 来源选择规则

以日期为边界选择数据源：请求日期当天只要存在 session，就完全使用 session；否则回退 activity_logs。这样既保留升级前历史，又避免同一天迁移或双写产生重复计数。

## 范围统计

先查询请求范围内包含 session 的日期集合，将日期拆成 session 日期和 legacy 日期，分别复用现有聚合函数。随后合并 daily、分类、应用与 totals，并按原始请求日期顺序输出 daily。分类和应用按原有键累计、按有效时长倒序排列。

## 娱乐趋势

一次查询 session 日期及其娱乐时长，再仅为缺少 session 的日期查询旧日志。最终按日期列表合并，保证每个日期只使用一个来源。

## 测试

构造同一数据库：昨天只有旧日志，今天只有 session。验证日期范围同时返回两天时长与正确合计；验证娱乐趋势也同时包含两天数据。再运行完整回归、编译、发布构建和运行路径检查。

## 范围外事项

本批不迁移或删除旧表，不在同一天混合两个来源，不修改单日查询已有的正确回退逻辑。
