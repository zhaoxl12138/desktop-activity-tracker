# DayLens 可信计时与可执行洞察设计

## 背景与结论

对 `2026-06-11` 至 `2026-08-10` 的 6,782 条 Session 做只读分析后，用户的主要办公模式是 AI 协同型技术研发：ChatGPT/Codex、浏览器技术检索、Obsidian、Source Insight、MobaXterm 和 Notepad++ 形成高频往返的工作链。当前统计同时存在两类产品缺口：

1. `effective_seconds` 混合键鼠参与时间和带音频的视频播放时间，无法回答“实际投入了多少注意力”。
2. 分类和采样逻辑在历史期间多次变更，但趋势图没有标出统计口径断点，前后数据看似可比、实际并非同一口径。
3. 高频应用切换既可能是 ChatGPT 与代码工具之间的正常协作，也可能是社交或娱乐打断；现有 Session 数不能区分二者。
4. 日报提供大量事实，但没有把事实压缩成一条可信、可执行且有证据的建议。

本设计采用“可信数据层优先、洞察层紧随其后”的顺序实现。首个版本完全本地运行，不调用云端模型，不上传窗口标题，不直接改写历史 Session。

## 方案比较

### 方案一：可信数据层后接洞察层（采用）

先建立新的时间语义、规则版本和置信度，再让洞察引擎只消费达到门槛的数据。优点是结果可解释、可测试，用户不会被错误建议误导；代价是需要数据库迁移并保留一段新口径数据后，部分长期洞察才会出现。

### 方案二：两层并行，所有洞察带低置信标记

可以更快看到洞察，但 UI 和业务逻辑必须同时处理新旧口径，首次版本复杂度更高，低置信建议也容易造成认知负担。

### 方案三：直接用现有日报生成自然语言总结

实现最快，但会把音频播放当成注意力投入，把正常研发工具切换当成分心，并放大历史规则变化造成的假趋势，因此不采用。

## 范围

### 本次包含

- Session 新增参与时间、被动媒体时间和计量版本字段。
- 保留 `effective_seconds` 兼容现有查询和报告。
- 新记录按互斥口径满足：`duration_seconds = engaged_seconds + passive_seconds + idle_seconds`，允许一个采样周期的整数误差。
- 分类结果保存稳定的规则指纹，用于判断两个区间是否可比。
- 数据健康服务提供覆盖率、计量版本、规则版本、组成异常和可比性结论。
- 首页显示可信时间摘要、数据置信度和最多一条建议。
- 本地洞察引擎识别优势时段、工作趋势、协作型工具切换和外部打断。
- 旧记录保持原样，标记为 legacy 口径；趋势和洞察不得把 legacy 与新口径直接混合比较。

### 本次不包含

- 不使用大模型生成文案。
- 不做任务名称或项目的自动语义分类。
- 不修改或删除历史记录。
- 不把普通的 ChatGPT、代码、终端、笔记切换直接定义为分心。
- 不加入强制专注、应用封锁、提醒轰炸或后台联网。

## 可信计时模型

### 四种时间语义

1. **前台占用时间**：沿用 `duration_seconds`，表示应用作为前台 Session 被观察到的采样时间。
2. **参与时间**：新增 `engaged_seconds`。键鼠活动未超过普通空闲阈值时计入，代表用户参与的近似值。
3. **被动媒体时间**：新增 `passive_seconds`。仅当前台分类为视频、目标 PID 确有音频，且键鼠已超过普通空闲阈值时计入。
4. **空闲时间**：沿用 `idle_seconds`。既不满足参与条件，也不满足被动媒体条件时计入。

三个组成字段互斥。音频播放不再重置键鼠空闲计时器。视频在键鼠活跃窗口内计为参与时间，超过窗口后有声音计为被动媒体，无声音计为空闲。

`effective_seconds` 为兼容字段：新记录中等于 `engaged_seconds + passive_seconds`。现有报表继续可用，但新 UI 不再把它单独命名为“有效时间”。工作与专注统计只使用工作分类的 `engaged_seconds`；媒体消费同时展示参与和被动两部分。

### Session 与待确认切换

现有跨域 grace period 同样维护参与、被动和空闲三个计数器。确认切换、取消切换、持久化重试和关机恢复时，三个计数器必须守恒。旧的 `effective_during_grace` 保留为兼容输出时的派生值，不再作为唯一真值。

### 版本字段

`activity_sessions` 新增：

- `engaged_seconds INTEGER DEFAULT 0`
- `passive_seconds INTEGER DEFAULT 0`
- `metric_version TEXT DEFAULT 'legacy'`
- `classification_version TEXT DEFAULT 'legacy'`

新记录使用固定常量 `attention-v1`。分类器对最终合并后的分类规则做规范化 JSON 和 SHA-256 摘要，保存短指纹。规则顺序或 YAML 格式变化不应改变指纹，实际匹配内容变化必须改变指纹。

迁移只添加字段，不回填或推断旧记录。这样避免根据聚合值伪造历史参与时间。

## 数据可信度与可比性

新增 `trusted_metrics_service`，返回范围级健康信息：

- Session 数与有记录日期覆盖率。
- legacy、新计量版本和不同分类版本占比。
- 计时组成不守恒数量。
- 重复 Session ID、负数和墙钟时间异常。
- `high`、`medium`、`low` 三档置信度及明确原因。

判定规则：

- 全部目标 Session 使用同一非 legacy 计量版本、同一分类版本，组成异常率不超过 0.5%，为 `high`。
- 数据完整但包含多个分类版本，或 legacy 占比不超过 20%，为 `medium`。
- legacy 占比超过 20%、版本无法比较、缺失日期超过 20% 或存在严重计时异常，为 `low`。

趋势比较只有在两边计量版本一致时才允许显示增减结论。分类版本不一致时可以比较“总参与时间”，但分类维度结论必须隐藏并显示“规则已变化”。

## 本地洞察引擎

新增纯函数式 `insights_service`，输入范围统计和可信度，输出零或一条主建议。每条建议包含：

- `kind`
- 简短标题
- 证据句
- 推荐动作
- 置信度
- 使用日期范围
- 是否因版本或样本不足而抑制

### 候选洞察

按以下优先级选择一条，避免首页信息过载：

1. **数据健康**：低置信时只解释问题和修复方向，不评价用户效率。
2. **优势时段**：最近 14 天至少 5 个有效工作日、某两小时窗口贡献至少 30% 的工作参与时间时，建议保护该窗口。
3. **外部打断**：工作前后 15 分钟内夹有社交或娱乐 Session，且一周至少 8 次时，建议在优势时段静音或集中处理。
4. **趋势变化**：最近 7 天与此前 7 天可比，参与工作时间变化超过 20% 且绝对差超过 60 分钟时，说明趋势并给出维持或复盘动作。
5. **协作工作流**：同一工作域内两个以上工具反复切换，但非工作打断较少时，描述为协作型工作流，不输出“过度切换”警告。

所有文案使用规则模板生成，证据数值可以从数据库复算。样本不足时不凑建议，显示“继续记录以形成可靠洞察”。

## 数据流与模块边界

1. `SessionTracker` 只负责每个采样周期的互斥计数和 Session 状态机。
2. `session_repository` 只负责新字段持久化与读取。
3. `stats_repository` 提供按日期范围聚合的参与、被动和空闲数据，不包含建议规则。
4. `trusted_metrics_service` 判断数据是否健康、版本是否可比。
5. `insights_service` 只基于聚合输入生成候选洞察并排序。
6. `dashboard_service` 组合今日摘要、健康状态和一条洞察。
7. Qt 页面只渲染 view model，不直接查询或解释数据。

这些边界保证计时算法、可信度规则和洞察文案可以独立测试，也避免继续扩大 `today_overview.py`。

## 界面设计

首页原有“有效时间”改为“参与时间”，旁边增加“被动媒体”。数据不足或 legacy 时在数值旁显示黄色“口径待稳定”标记。

首页增加一张紧凑的“今日建议”卡：

- 第一行显示建议标题和高/中/低置信标识。
- 第二行显示一条证据。
- 第三行显示一个具体动作。
- 低置信时卡片变为“数据健康”，不显示效率评价。

趋势图遇到分类版本变化时显示竖向断点；第一版可先以断点说明文本代替复杂绘图标线，避免扩大 UI 风险。

日报总览同步新增参与时间、被动媒体时间和数据可信度。CSV/Markdown 的旧字段保留，新增字段追加在后，不破坏既有消费者。

## 错误处理与兼容

- 数据库迁移幂等执行；字段存在时不得重复添加。
- 老数据库打开后仍能查询旧日报和软件统计。
- 新字段写入失败时整条 Session 事务失败，进入现有恢复队列，不允许部分计数写入。
- 音频检测失败按“无音频证据”处理，不产生被动媒体时间。
- 置信度或洞察计算异常只隐藏新卡片并写日志，不阻塞记录线程和主页其余内容。
- 所有新统计在后台快照刷新链路中计算，不从 Qt 主线程做全库扫描。

## 测试策略

### 计时状态机

- 有键鼠活动的视频计为参与。
- 超过普通空闲阈值且目标 PID 有音频的视频计为被动媒体。
- 无音频时计为空闲。
- 音频不能重置真实键鼠空闲计时。
- 普通工作、社交、跨域 grace、持久化失败重试、跨日和系统间隙均满足计数守恒。

### 数据库与查询

- v3 数据库幂等迁移到新版本且不修改旧 Session 值。
- 新 Session 四个字段完整往返。
- 新旧数据混合查询能返回 legacy 占比和版本集合。

### 可信度与洞察

- high/medium/low 的边界均有固定样例。
- 版本不一致时抑制分类趋势结论。
- 优势时段、外部打断、趋势、协作工作流按优先级只返回一条。
- 样本不足和低置信时不输出行为评价。

### UI 与回归

- 首页快照包含新字段，旧组件仍可渲染。
- 参与/被动标签在深色和浅色主题下不溢出。
- 日报与导出保留原字段并追加新字段。
- 完整测试、GUI smoke、数据库迁移测试和 Release 打包通过。

## 验收标准

- 新 Session 的 `duration_seconds` 与三个组成字段在一个采样周期容差内守恒。
- 带音频但无键鼠活动的视频不再增加工作参与时间。
- 历史 legacy 数据不会与 `attention-v1` 数据产生无标记的百分比趋势。
- ChatGPT 与代码、终端、笔记之间的正常往返不会被直接标记为分心。
- 首页最多显示一条带证据、动作和置信度的本地洞察。
- 新功能关闭或异常时不影响核心记录、历史查询和报告生成。
