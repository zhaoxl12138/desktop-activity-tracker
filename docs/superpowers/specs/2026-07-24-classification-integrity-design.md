# DayLens 分类可信度修复设计

## 目标

修复三项会直接影响统计可信度的问题：

1. 浏览器窗口被通用浏览器规则提前截获，YouTube、GitHub、微信读书等内容无法进入对应分类。
2. 当前进程没有音频会话时，后台其他软件的声音会让前台视频被误判为持续播放。
3. 首次应用扫描或向导保存空标题关键词时，会覆盖内置标题关键词。

本批次不修改历史 Session，不重构完整分类评分系统，也不改变用户已经保存的非空自定义关键词。

## 方案比较

### 方案 A：调整现有优先级并集中浏览器识别（采用）

- 建立统一的浏览器进程集合，覆盖 Chrome、Edge、Firefox、360、Brave、Opera、Vivaldi 等已有配置中的浏览器。
- 浏览器先执行内容分类，再执行 `browser_general` 回退。
- `browser_general` 不参与最高优先级的“进程 + 标题”竞争。
- 音频检测找不到目标 PID 的会话时返回 `False`。
- 自定义标题关键词为空时继承内置关键词。

优点是改动范围小、兼容现有配置、容易用回归测试覆盖。

### 方案 B：重写为统一评分分类器

为进程、标题、正则、强弱关键词和排除词统一评分。长期更灵活，但会改变大量已有规则的优先级，不适合与当前紧急修复捆绑。

### 方案 C：只修改当前数据库规则

可以暂时缓解 Chrome 问题，但 360 等浏览器仍无法进入内容匹配，首次扫描后也会再次复发，不能解决根因。

## 详细设计

### 浏览器分类

分类顺序调整为：

1. 非通用分类的“进程 + 标题”精确匹配。
2. 对所有已识别浏览器执行标题内容匹配。
3. 非浏览器按进程名匹配具体分类。
4. 浏览器落入 `browser_general`。
5. 其他应用落入 `other`。

内容匹配仍保留现有“学习分类优先于娱乐”的策略。例如标题同时命中视频站点和教程关键词时，进入学习分类。

验收用例：

- `chrome.exe + YouTube - Google Chrome` → `video`
- `360ChromeX.exe + bilibili - 360极速浏览器X` → `video`
- `chrome.exe + GitHub - Google Chrome` → `coding`
- `chrome.exe + 新标签页 - Google Chrome` → `browser_general`

### 音频检测

只允许目标 PID 的实际峰值作为播放证据。目标 PID 没有音频会话、读取失败或 PID 为空时均返回 `False`。保留 `is_any_playing()` 供诊断使用，但 SessionTracker 不再通过它间接认定前台视频有效。

### 规则继承

合并自定义规则时：

- 非空 `process_names` 使用用户保存值。
- 非空 `title_keywords` 使用用户保存值。
- 空 `title_keywords` 继承配置文件中的内置关键词。
- 用户明确保存的非空关键词不与内置关键词强制合并。

这与规则管理页面现有的展示行为保持一致，并保护首次扫描流程。

## 测试

新增回归测试覆盖：

- Chrome 和 360 的内容优先分类。
- 浏览器通用标题仍回退到浏览器分类。
- 无目标音频会话时不使用其他进程声音。
- 首次向导生成空关键词后，分类器仍保留内置关键词。

完成后运行完整 `py -m pytest -q`，再打包 release、刷新桌面快捷方式并重启 DayLens。
