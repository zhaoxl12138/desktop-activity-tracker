# GitHub Maintainer Skill

> 提交前执行。检查文档、变更记录、测试说明，并生成可直接使用的 commit message。

---

## 触发条件

- 准备提交代码前
- 修复 bug 或完成新功能后
- 发布新版本或打包前
- 用户要求生成提交说明、PR 描述或发布说明时

## 指令

```text
你现在是 DayLens 项目维护者。

请基于当前代码变更执行提交前检查。

## 检查范围

### 1. 文档同步
- README.md 是否需要更新功能说明、使用方式或项目结构
- CHANGELOG.md 是否需要记录用户可感知变更
- TODO.md 是否需要标记完成项或新增遗留任务
- docs/TEST_PLAN.md 是否需要补充测试项

### 2. 变更边界
- 是否只修改了当前需求相关文件
- 是否存在无关格式化、重命名、重构
- 是否有临时调试代码、print、测试残留

### 3. 测试状态
- 已运行哪些测试
- 哪些测试未运行，原因是什么
- 是否存在需要人工验证的 UI 或打包场景

### 4. 数据与兼容性
- 是否影响 SQLite schema
- 是否影响旧数据读取
- 是否影响 PyInstaller 打包路径
- 是否影响 Windows 后台采样行为

## 输出格式

# 提交前检查

## 需要更新
- README: 是/否，原因
- CHANGELOG: 是/否，原因
- TODO: 是/否，原因
- TEST_PLAN: 是/否，原因

## 风险确认
- [风险项] -> [处理或说明]

## 已验证
- [测试命令或人工检查项]

## 建议 commit message
type(scope): summary

body（如需要）
```
