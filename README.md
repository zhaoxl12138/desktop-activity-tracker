# DayLens

> 看清时间花在哪里。

DayLens 是一个本地 Windows 桌面应用，用来记录前台窗口使用情况，分类统计活跃时间、挂机时间、娱乐时间和社交通讯时间，并生成日报、周报、月报。

## 功能

- 自动记录前台窗口和会话切换
- 区分活跃时间与挂机时间
- 统计分类分布、趋势、时间线、Top 软件
- 侧栏“数据统计”统一容纳软件、分类、目标与成果和实时监控；设置中心位于最后。实时监控和原有分类纠错复用原页面，不改变记录线程。
- “数据统计”默认打开实时监控；分类统计默认查看近 7 天，也可切换今日、近 30 天或自选日期范围。分类明细与所选时段使用同一口径。
- 分类管理的本地规则默认按应用管理，支持搜索、添加与移除；标题关键词、手动进程编辑和计时策略收进高级设置。原有规则保留；本地草稿测试标题可空，与保存复用相同的继承/归属合并逻辑，不调用AI，也不改历史记录。
- “游戏娱乐”和“视频娱乐”分别保留主动交互、被动播放两种计时策略；旧版同名规则在界面中区分。桌面和任务栏视为空闲，主动打开的文件夹窗口仍正常计时。
- 工作节奏／娱乐时间的近7天、近30天均包含今天；无记录日期留空，底部统一显示日均时长、最高一天和总时长。工作使用蓝色柱图，娱乐近30天保留日历热力图，日期下标与柱子一一对应。
- 点击近7天工作／娱乐图表中的某一天，查看该日活动详情；横轴适配首末有效活动，默认突出有效活动满5分钟的连续同应用同标题事件，可切换显示全部事件
- 全天活动详情支持点击分类标签筛选时间轴与明细；筛选不改变全天有效时长。设置页底部显示本月 AI 费用保守估算，无法读取时不会显示为零。
- 导出 Markdown / CSV 报告
- 支持同步到 Obsidian
- Obsidian 自动归档到 `年份/年份-月份/文件名`，例如 `2026/2026-10/2026-10-26.md`；已有年份/月份路径不会重复嵌套。周报按结束日、月报按所属月份归档；同一报告原子更新。历史文件整理工具 `tools/organize_obsidian_reports.ps1` 默认只预览，执行前备份并把旧重复副本送回收站。
- 每日目标：在“统计 → 目标与成果”设置最多 3 项大类时间/成果目标；时间目标比较可信主动参与，成果目标只接受用户手动确认
- 周报在原有内容后增加“计划 / 投入 / 已确认成果”，不把目标达时长当成完成成果

任务链、本地任务分析和云端任务建议已从应用界面及后台调用中移除，旧设置不能恢复这些入口。历史任务归属等 `data/intelligence/` 派生文件保留，供旧目标及报告兼容读取，不删除或改写原始会话、历史报告和分类；正常计时与分类规则不变。

每日目标也保存在同一规范 `intelligence/` 目录的独立派生 JSON。未设置目标不会产生目标判断；没有可信会话时显示“证据不足”，不补成 0。V1.7 不自动读取 Git 仓库或笔记作为成果证据；周报中的“用户确认”仅代表用户手动勾选。

全天活动详情只在打开、切换日期或手动刷新时读取本地会话，不调用AI，不恢复任务链，也不修改统计。分类横轴自动适配当天首末有效活动的前台范围，首尾向外取整到半小时；例如09:42–12:40显示09:30–13:00，中间空闲/缺口保留真实长度。刻度按跨度和宽度自适应，工作学习、娱乐、社交、投资等大类分行，较长色块显示应用名称。没有框选、缩放或参与比例轨；仅首尾空白被裁切，全天记录/统计和≥5分钟明细筛选不变。没有有效活动时保留当日参照并说明状态。色块表示前台记录范围，不等于全程有效；空闲、无记录、未来、异常分别标识，含空闲的记录不猜测空闲位置，旧口径不补造主动／被动分项。异常或重叠记录会提示无法可靠展开，未展开时长不代表原记录被扣减；小屏幕可滚动查看全部内容。

## 运行

### 发布版

解压发布包后，运行 `DayLens.exe`。

### 源码启动

```bash
pip install -r requirements.txt
python -m daylens.main
```

### 构建发布版

```bash
python tools/build_release.py
```

仅构建并验证隔离发布包、不退出或替换当前程序时，使用 `python tools/build_release.py --stage-only`。

构建完成后，以 `release/` 作为唯一发布目录。

### 清理历史构建产物

```bash
python tools/cleanup_runtime_artifacts.py
python tools/cleanup_runtime_artifacts.py --apply
```

默认是 `dry-run`，只列出将清理的 `build/`、`build_temp/`、`dist/`、`DayLens/`。  
如果需要把 `release/` 也一起清掉，再额外加 `--include-release`。

## 仓库目录

- `src/`：源码
- `tests/`：测试
- `config/`：默认配置
- `assets/`：静态资源
- `data/`：本地数据库与运行时数据
- `reports/`：导出的日报、周报、月报
- `release/`：当前发布版目录
- `dist/` / `build/` / `build_temp/` / `DayLens/`：构建或历史产物
- `tools/cleanup_runtime_artifacts.py`：清理历史构建目录

更完整说明见 `docs/repository-layout.md`。

## 开发约定

- 改代码只改 `src/`
- 运行数据只写入 `data/`、`reports/`
- 不提交 `build/`、`dist/`、`release/`、`DayLens/` 等构建产物
- 清理历史构建目录统一使用 `tools/cleanup_runtime_artifacts.py`
- 提交前优先跑自动化测试
